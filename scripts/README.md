# Скрипты

[![huix](https://img.shields.io/badge/huix-наверх-222222?style=for-the-badge&logo=nixos&logoColor=white)](../README.md)

Рукописные shell-обёртки, рассчитанные на путь `$HUIX/scripts`. Часть из них дёргается биндами Hyprland, часть — systemd-юнитами и Nix-обёртками из [программ](../home-manager/programs/README.md)

## Что внутри

| `sync.sh`                      | авто-синк конфига: `git pull --rebase --autostash` → `add` → `commit` → `push`, на старте сессии и после каждого `nixos-rebuild`                                                                                                                                                                                                                                                                                                          |

## Тонкости

- **`sync.sh` коммитит и пушит всё застейдженное** на старте сессии и после каждого `nixos-rebuild` — не оставляй в дереве то, чего не хочешь видеть в истории. При этом он делает `add -u` (только отслеживаемые), так что новый файл, забытый без `git add`, тихо не уедет в upstream
- пути не хардкодь — бери `$HUIX` в скриптах и `huixDir` в Nix
- многие скрипты завязаны на рантайм-state в `~/.local/state/huix/` (тема, шейдер) — он переживает логаут/ребут и восстанавливается на reload Hyprland
- у `claude-account.sh` отдельного state-файла нет: активный профиль это и есть цель симлинка `~/.claude`, читается через `readlink`. Обратная сторона — пути резолвятся лениво, так что смена профиля догоняет уже запущенные сессии (обновление токена уедет в новый профиль); `use` про живой `claude` предупреждает, но переключает
- `CLAUDE_CONFIG_DIR` прибит константой `$HOME/.claude` в [`programs/cli/claude.nix`](../home-manager/programs/README.md) — не «путь профиля», а именно дефолтный каталог конфига. Нужен только чтобы `.claude.json` лёг **внутрь** профиля: бинарник ищет его рядом с каталогом и переписывает через `rename(2)`, который заменил бы симлинк по такому пути обычным файлом и молча сломал изоляцию аккаунтов
- общее максимально: на профиль изолированы только `.credentials.json` и `.claude.json` (в нём `oauthAccount` — личность аккаунта, обязана жить рядом с токеном, иначе параллельные сессии перетрут друг друга). Из-за этого MCP/интеграции user-scope и trust-флаги папок между аккаунтами не ходят — общий MCP заводи через `.mcp.json` в проекте. Общий `history.jsonl` пишется обеими сессиями: при одновременной работе строки истории теоретически могут перемешаться (не критично, это только `↑`-история промптов)
- `claude-shared` синкается между `nixos-pc` и `nixos-laptop` через Syncthing (декларативно в [`syncthing.nix`](../nixos/services/tools/syncthing.nix), аддитивно — `override*=false`, чтобы не задеть `myWiki`, который ходит через телефон). Чаты/планы/задачи ключуются уникально и объединяются, singleton-файлы (`settings.json`, `MEMORY.md`) при конфликте дают `.sync-conflict-*`. Куки не синкаются — `/login` на каждом хосте свой
- **всё содержимое Клода лежит там же и обычными файлами** — включая `commands/`, `agents/` и статусную строку `statusline.sh`, которая раньше жила в этом каталоге. Декларативно их раскладывать нельзя: HM кладёт файлы симлинками в `/nix/store/<хеш-генерации>/…`, а Syncthing утащил бы такой симлинк на второй хост, где этой генерации нет
- `init` при миграции обрабатывает глобальный `CLAUDE.md` особо: непустой уезжает в `CLAUDE.md.bak-init-*` внутри профиля, а не промоутится в общий автоматически — глобальную память сливаешь в `claude-shared/CLAUDE.md` руками (она у людей/машин разная по нюансам)

## Применение

Скрипты подключаются либо биндами в `home-manager/desktop/hyprland/hyprland.conf`, либо Nix-обёртками (`writeShellApplication`), которые кладут зависимости в PATH
