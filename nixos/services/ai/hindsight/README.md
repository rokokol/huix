# Hindsight

Общая долговременная память pi и Hermes на станции. Модели извлечения фактов и эмбеддингов задаёт [ai-models.nix](../../../../lib/ai-models.nix); локальная база не означает локальную обработку — содержимое операций памяти передаётся настроенному провайдеру

## Доступ и жизненный цикл фактов

API слушает loopback, доступ с рабочих машин проходит через прокси частной сети. Для API и MCP нужен отдельный токен из SOPS; ключ OpenRouter остаётся у службы станции. Клиентская конфигурация pi находится в [memory.nix](../../../../home-manager/programs/agents/pi/memory.nix), Hermes — в [hermes.nix](../hermes/hermes.nix)

Ранжирование выдачи делает `qwen/qwen3-reranker-8b`, единственная модель реранка в ZDR-каталоге OpenRouter, и обслуживает её там один хостер. Его перегрузка возвращает 503, поэтому цепочка оканчивается fusion-only реранкером: recall тогда ранжирует хуже, но не отказывает. Оценку кандидата и лимит на документ задаёт [ai-models.nix](../../../../lib/ai-models.nix)

Расход Hindsight дашборд берёт из счётчика отдельного ключа `openrouter-hindsight-api-key`, на котором живут все модели службы, а не оценивает по токенам: своего счётчика токенов у эмбеддингов и реранка нет, а цена в каталоге моделей приходит нулевой — см. `PITFALLS.md`. Ключ и таймер, который выгружает счётчик в Prometheus, живут в [monitor.nix](monitor.nix), причина отдельного ключа — в `DEVIATIONS.md`

Тот же таймер считает вызовы, за которые заплатил реранк: их видно только в трассах банка, потому что счётчик вызовов службы ведёт одни LLM-скоупы. Трассы живут сутки, поэтому таймер складывает число по дням в своё состояние и отдаёт накопленный счётчик — история копится с первого запуска, а не с момента установки Hindsight

Обычный набор инструментов позволяет искать и сохранять факты, а устаревшие помечать через `invalidate_memory`. Инвалидация относится к идентификатору факта: запись сохраняется, но исключается из обычного поиска и консолидации. Для последующего аудита её можно получить отдельным запросом с состоянием `invalidated`; автоматическая глубокая рефлексия по таким записям не настроена

Шаблон бэнка объявляет mental model `owner-working-brief`: синтезированный брифинг владельца — активные проекты, системы и службы, устойчивые предпочтения, принятые решения, точные пути и команды, открытая работа. Пересчитывается он сам по расписанию из [service.nix](service.nix), где задан и запрос, по которому модель собирается; на клиенте расписания нет

Читают брифинг по id инструментом `get_mental_model` — он входит в allowlist службы, поэтому доступен через MCP, без shell и без токена в команде. Инструменты, которые mental models создают, пересчитывают и удаляют, в allowlist не входят: модель объявляет шаблон, а не клиент. В ответе есть `last_refreshed_at` — когда пересчёт последний раз завершился, и `is_stale` — писались ли после этого воспоминания в области модели, то есть переписал бы её ближайший пересчёт

Выбор инструментов на клиенте не заменяет авторизацию: обладатель токена может обратиться к другим разрешённым сервером операциям

## Перед первой активацией

- Владелец создаёт объявленные [дисковой конфигурацией станции](../../../station/disko.nix) субтома на существующем Btrfs-томе; создание службы не требует форматирования или переразметки диска
- PostgreSQL должен видеть смонтированное хранилище, а не пустой каталог на корневой файловой системе. Стартовые проверки требуют нужный mountpoint и Btrfs-субтом; существующий кластер нельзя заменять или инициализировать поверх него
- Кластер нужен в UTF-8. Подготовительная служба создаёт pgvector от имени PostgreSQL до запуска непривилегированного приложения
- Должны расшифровываться серверные и клиентские секреты SOPS, а ключ OpenRouter — иметь подходящие ограничения моделей, хостеров и приватности
- Ключ `openrouter-hindsight-api-key` должен разрешать `qwen/qwen3-embedding-8b`, `z-ai/glm-5.3-flash` и `qwen/qwen3-reranker-8b` с их хостерами в режиме ZDR: клиент Hindsight не передаёт параметры приватности в запросы эмбеддингов и реранка, ограничения живут в политике ключа
- Для эмбеддингов штатный адаптер не передаёт параметры приватности OpenRouter в теле запроса: ограничения должны обеспечиваться политикой ключа на стороне OpenRouter, а не предположением о настройках чат-запросов
- Активацию выполняет владелец. После неё нужно проверить здоровье служб, отказ API без токена, доступ обоих клиентов и первый успешный бэкап; локальный trial не подтверждает сетевую доступность станции

## Резервные копии и восстановление

[backup.nix](backup.nix) создаёт согласованный дамп PostgreSQL, снимает Btrfs-снимки завершённых дампов и добавляет их в существующий restic-бэкап станции. Живой каталог PostgreSQL не используется вместо логической резервной копии. Пути и расписания определены в модуле и конфигурации хоста

Для проверки восстановления выберите завершённый дамп из каталога копий, снимка или restic и распакуйте zstd в закрытый временный каталог. Проверьте архив через `pg_restore --list`, затем создайте отдельную пустую UTF-8 базу с непривилегированным владельцем и заранее установите в ней pgvector от имени администратора PostgreSQL

Восстанавливайте в эту отдельную базу через `pg_restore --exit-on-error --no-owner --no-acl --no-comments --role <владелец> --dbname <проверочная-база> <дамп>`. Проверьте факты с кириллицей, наличие векторных данных и владельца таблиц. Успешное чтение оглавления само по себе не доказывает полное восстановление

Замена рабочей базы — отдельная операция владельца при остановленной службе Hindsight и сохранённой копии прежней базы. Проверка восстановления не должна удалять или перезаписывать рабочий кластер

Дампы, снимки и restic на одном диске помогают против ошибочных изменений, но не отказа диска. Отдельное внешнее место хранения ещё требуется
